# Очистка Данных Сервера

## Что это такое?

`/server manage` — служебная панель для полной перенастройки сервера. Она позволяет безопасно стереть накопленные данные бота: историю смен, приказы, отпуска, привязки званий.

Когда это нужно:

- вы хотите начать учёт заново (новый сезон, реформа фракции);
- нужно почистить данные конкретного ушедшего сотрудника;
- старые записи мешают статистике и рейтингам.

## Как открыть

```
/server manage
```

Команда доступна только участникам с ролью из раздела [«Права Доступа»](/ru/guides/bots/department-oversight/permissions) («Роли Настроек»). Панель состоит из пяти страниц.

***

## Страницы панели

### Введение
Краткое описание возможностей и предупреждение о последствиях.

### Отпуска и ПА
- очистить ожидающие заявки;
- удалить всю историю отпусков;
- удалить всю историю ПА.

### Подразделения
- сбросить **все** данные подразделений: префиксы и настройки отображения;
- удалить данные только конкретного пользователя.

### Звания
- очистить все повышения, понижения, переводы и принятия;
- отвязать звания от всех пользователей;
- либо то же самое — только по выбранному пользователю.

### Смены
- удалить все / завершённые / активные смены;
- удалить смены конкретного типа.

<Callout icon="circle-check" color="#22C55E">
  Активные смены удаляются корректно: бот снимает роль дежурства и роль перерыва, убирает префикс из ника и отправляет сотруднику уведомление в ЛС. Никто не останется «зависшим на смене».
</Callout>

***

## Защита от случайного удаления

Панель построена так, чтобы стереть данные случайно было невозможно:

1. Каждое массовое действие помечено красными кнопками опасности.
2. Перед выполнением нужно **вручную ввести фразу подтверждения**: `Я ГОТОВ УДАЛИТЬ ДАННЫЕ`.
3. Сессия панели живёт 15 минут и работает только у того, кто её вызвал.
4. Каждое действие записывается в [каналы логов](/ru/guides/bots/department-oversight/logs).

<Callout icon="triangle-exclamation" color="#EF4444">
  Удалённые данные восстановлению не подлежат. Если сомневаетесь — начните с очистки данных одного пользователя, а не всей базы.
</Callout>
